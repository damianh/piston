## Phase 2: Roslyn Diagnostics, Semantic Search, AST Inspection - Completed

### What was done
- **Bug fix**: Converted `WorkspaceHost` from static class to sealed instance class — the `MSBuildWorkspace` and `Solution` are now stored as fields, fixing a bug where workspace state was lost between calls (local variable passed by value)
- Added `GetDiagnostics` handler: compiles projects, filters to Error/Warning severity, returns `DiagnosticsResponse`
- Added `SemanticSearch` handler: uses `compilation.GetSymbolsWithName()` + `SymbolFinder.FindReferencesAsync()` to find all references to a symbol
- Added `GetAst` handler: walks syntax tree building `AstNode` DTOs for declaration nodes only, respecting `MaxDepth`
- Added request DTOs: `GetDiagnosticsParams`, `SemanticSearchParams`, `GetAstParams`
- Added response DTOs: `DiagnosticResult`, `DiagnosticsResponse`, `SymbolReference`, `SemanticSearchResponse`, `AstNode`, `AstResponse`
- Updated `RoslynJsonContext` with all new types for source-gen serialization
- Added `GetDiagnosticsAsync`, `SemanticSearchAsync`, `GetAstAsync` to `IRoslynWorkspace`
- Implemented proxy methods in `RoslynWorkspaceProxy` following existing serialize-send-deserialize pattern
- Used method overloads (no optional parameters) per C# standards

### Build status
- Solution builds with 0 warnings, 0 errors

### Notes for next person
- `ProjectInfo` is ambiguous between `Microsoft.CodeAnalysis.ProjectInfo` and `Piston.Roslyn.Messages.ProjectInfo` in the Worker — resolved with `Messages.ProjectInfo` qualifier
- Phase 3 could add: `applyRefactoring` and `fileChanged` methods
- Integration tests would require a test .csproj/.sln to load into MSBuildWorkspace
